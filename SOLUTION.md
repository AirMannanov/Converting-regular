# Вводная информация
- **Язык и парадигма.**
Для реализации был выбран **Common Lisp**, поскольку он хорошо подходит для задач, связанных с текстовой обработкой. Входные данные удобно валидировать с помощью функциональных инструментов и преобразовывать в специальные внутренние структуры (лексемы) для дальнейшей обработки.
Детерминированность выражений позволяет гибко и надёжно обрабатывать различные случаи.
Следует отметить, что само задание достаточно сложно реализовать в рамках чисто функциональной парадигмы, поскольку предложенные алгоритмы больше соответствуют императивному стилю программирования. Это связано с использованием структур данных (таких как матрицы или графы), которые подвергаются изменениям в процессе выполнения основного алгоритма. Поэтому в реализации программы присутствуют элементы из императивной парадигмы: `setf` и `dotimes`.
- **Алгоритм.** 
Программа использует матричную форму state-elimination: на каждом шаге матрица переходов дополняется выражениями вида `R_ik (R_kk)* R_kj`, пока не будут учтены все промежуточные состояния.
- **Использование ИИ.** ИИ использовался при написании функции перевода из внутреннего представления РВ в строковый (естественный для РВ формат) и рефакторинге кода.
- **Замечание.** Следует отметить, что хотя в алгоритме предусмотрены отдельные шаги по упрощению эквивалентных регулярных выражений, это не гарантирует получение минимального (наикратчайшего) регулярного выражения на выходе.

## Реализация
1. На вход подаются данные, которые проходят валидацию функцией `read-and-parse`
1. Дальше данные подаются на вход основной функции `automaton-to-regex`, переводящую ДКА во внутренние представление РВ с использованием лексем. Пример «естетсвеннго» РВ `a|b*`, пример во внутреннем представлении `(UNION (LITERAL a) (STAR (LITERAL b)))`.ы
1. Полученная внутренняя структура транслируется в «естетсвенный» формат функцией `expression->string`


## Запуск
```bash
sbcl --script automaton-regex.lisp < input.lisp
```

## Формат ввода
- На стандартный ввод подаётся одна S-выражение - список рёбер `((FROM LABEL TO) …)`.
- Стартовое и конечно состояния: H и S соответственно
- Метка `eps` интерпретируется как переход по пустой цепочке.

Пример:
```lisp
((H a H) (H eps S))
```

## Тесты
Набор тестов находится в директории `tests` и покрывает типовые ситуации:

| Описание ввода | Ожидаемое выражение |
| --- | --- |
| `((H a S))` | `a` |
| `((H a H) (H b S))` | `a*b` |
| `((H a A) (H b B) (A c S) (B d S))` | `ac\|bd` |
| `((H eps A) (A a S))` | `a` |
| `((H w A) (A a A) (A w B) (B b B) (B w S))` | `wa*wb*w` |
| `((H a S) (S b S))` | `ab*` |
