# **Вариант РЕГУЛЯРНОЕ ВЫРАЖЕНИЕ (РВ)**: Построение регулярного выражения по конечному автомату.

По заданному конечному автомату построить соответствующее регулярное выражение,
описывающее язык (цепочки символов), распознаваемый этим автоматом. Регулярное выражение
строится из терминальных символов (из которых собственно и состоят цепочки), в этом качестве
выступают строчные (маленькие) латинские буквы. Выражение задает структуру цепочек с
помощью скобок и нижеследующих операций (в порядке их приоритета):
1. итерация (звездочка Клини) * и непустая итерация + (например: x* , z+)
1. конкатенация (например: xy)
1. альтернатива | (например: a|b)

Например, a+|ab(x|y)* – это либо непустая цепочка из букв a (например, aaa), либо
цепочки, начинающиеся с букв ab, после которых идет произвольная последовательность из
букв x и y (abyxxyxy и др.).

Конечный автомат задается как ориентированный граф, вершины которого соответствуют
состояниям автомата и помечаются большими латинскими буквами. Во множество вершин
входит начальное состояние H и заключительное S. Рёбра графа соответствуют переходам между
состояниями автомата и помечены терминальными символами. Граф может быть записан как
список входящих в него рёбер, каждое ребро представлено трёхэлементным списком/кортежем
вида: <метка_вершины метка_ребра метка_вершины>.
Описание алгоритма построения регулярного выражения по конечному автомату – см.
[КА и Регулярные выражения](https://neerc.ifmo.ru/wiki/index.php?title=Преобразование_регулярного_выражения_в_ДКА) (вторая часть), а также [Три метода: ДКА в RegExpr](https://masters.donntu.ru/2017/fknt/gerbutova/library/article10_2.0.htm)


## Требования к выполнению ДЗ:
1) Программа должна быть сдана вместе с набором тестов, который помещается в виде комментария в текст программы (если текст объемный и/или много тестов, то тесты можно выложить в виде отдельного файла).
1) Программа сдается вместе с кратким (1-3 предложения) обоснованием/пояснением выбора языка и парадигмы программирования для решаемой задачи, которое размещается в виде комментария в начале текста программы.
1) В программе должны быть комментарии для основных структур данных и логических частей.
1) Следует указать (примерный) процент кода, созданного с помощью ИИ или других внешних источников (само использование не карается, но учитывается;  приветствуется 0 % заимствований)
1) В большинстве вариантов ДЗ при разработке программы следует продумать и использовать внутреннее представление (или типы) обрабатываемых данных/выражений (формул и т.п.), что упрощает решение.

### Особенности оценивания ДЗ:
Реализованные программы оцениваются  в интервале баллов, указанных для варианта, с учетом выбранного языка и сложности задачи.

#### Баллы за ДЗ повышаются:
- за использование средств языка, упрощающих решение задачи и делающих код более логичным и ясным (функционалы, типы данных и др.);
- за удачное внутреннее представление обрабатываемых данных;
- за логичную структуру программы и адекватное комментирование;
- за реализацию дополнительной функциональности.

#### Баллы за ДЗ снижаются:
- при несоблюдении дедлайна сдачи (загрузки программы в систему);
- при неполной реализации требуемых вариантом ДЗ возможностей программы;
- при усложнении решения задачи, которое может произойти из-за неудачного выбора языка и/или не использования его ключевых средств и/или неудачного внутреннего представления данных;
- при недостаточном обосновании выбора языка и парадигмы (или его отсутствии);
- при неполноте или отсутствии набора тестов, на которых проверялась программа;
- при отсутствии ключевых комментариев (для внутреннего представления обрабатываемых данных, основных функций/предикатов/структур данных).

# Решение

## Вводная информация

**[Ссылка на гитхаб](https://github.com/AirMannanov/Converting-regular)**

- **Язык и парадигма.**
Для реализации был выбран **Common Lisp**, поскольку он хорошо подходит для задач, связанных с текстовой обработкой. Входные данные удобно валидировать с помощью функциональных инструментов и преобразовывать в специальные внутренние структуры (лексемы) для дальнейшей обработки.
Детерминированность выражений позволяет гибко и надёжно обрабатывать различные случаи.
Следует отметить, что само задание достаточно сложно реализовать в рамках чисто функциональной парадигмы, поскольку предложенные алгоритмы больше соответствуют императивному стилю программирования. Это связано с использованием структур данных (таких как матрицы или графы), которые подвергаются изменениям в процессе выполнения основного алгоритма. Поэтому в реализации программы присутствуют элементы из императивной парадигмы: `setf` и `dotimes`.
- **Алгоритм.** 
Программа использует матричную форму state-elimination: на каждом шаге матрица переходов дополняется выражениями вида `R_ik (R_kk)* R_kj`, пока не будут учтены все промежуточные состояния.
- **Использование ИИ.** ИИ использовался при написании функции перевода из внутреннего представления РВ в строковый (естественный для РВ формат) и рефакторинге кода.
- **Замечание.** Следует отметить, что хотя в алгоритме предусмотрены отдельные шаги по упрощению эквивалентных регулярных выражений, это не гарантирует получение минимального (наикратчайшего) регулярного выражения на выходе.

## Реализация
1. На вход подаются данные, которые проходят валидацию функцией `read-and-parse`
1. Дальше данные подаются на вход основной функции `automaton-to-regex`, переводящую ДКА во внутренние представление РВ с использованием лексем. Пример «естетсвеннго» РВ `a|b*`, пример во внутреннем представлении `(UNION (LITERAL a) (STAR (LITERAL b)))`
1. Полученная внутренняя структура транслируется в «естетсвенный» формат функцией `expression->string`

## Запуск
```bash
sbcl --script automaton-regex.lisp < input.lisp
```

## Формат ввода
- На стандартный ввод подаётся одна S-выражение - список рёбер `((FROM LABEL TO) …)`.
- Стартовое и конечно состояния: H и S соответственно
- Метка `eps` интерпретируется как переход по пустой цепочке.

Пример:
```lisp
((H a H) (H eps S))
```

## Тесты
Набор тестов находится в директории `tests` и покрывает типовые ситуации:

| Описание ввода | Ожидаемое выражение эквивалентно|
| --- | --- |
| `((H a S))` | `a` |
| `((H a H) (H b S))` | `a*b` |
| `((H a A) (H b B) (A c S) (B d S))` | `ac\|bd` |
| `((H eps A) (A a S))` | `a` |
| `((H w A) (A a A) (A w B) (B b B) (B w S))` | `wa*wb*w` |
| `((H a S) (S b S))` | `ab*` |
